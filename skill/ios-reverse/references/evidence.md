# 证据卫生：哪些「发现」是假的

这份清单里每一条都是真实发生过的误判，不是假想。写下来是因为**假证据比没证据更危险**——
它会让你基于错误前提继续推理，越走越远。

## 1. slide 过期

**现象**：读到的代码和静态反汇编完全对不上，于是判断「二进制会自解密改写代码段」。

**真相**：进程重启后 `load_address` 变了，我用旧 slide 算地址，读到了别的函数的代码。
字节当然对不上。

**规则**：每次 `get_stats`（返回 process.pid）/ `list_loaded_images` / 重启目标后，重新 `get_macho_info` 拿 `load_address`。
「代码被改写」这种结论，必须在同一进程代内、用刚取的 slide、两次读数一致才能成立。

## 2. `hits == 0` 不等于「没执行」

四种可能必须逐条排除：

1. 地址算错（slide）
2. 函数确实没被调用（换触发路径）
3. hook 装失败但 API 返回了成功
4. 同一符号被重复 hook，GOT 只指向最后一个槽位，旧槽位永远 0 命中

**规则**：任何「这段代码不执行」的结论都要配一个**同轮的正对照**——
同一时刻另一个地址确实命中了。否则你证明的只是「你的观测手段坏了」。

## 3. 缓冲区生命周期

**现象**：抓到一堆看起来像配置的字符串（域名、版本号），以为是目标数据。

**真相**：那是 `free` 之后被复用的堆内存。真正的输出缓冲在函数返回瞬间就释放了。

**规则**：在**命中瞬间**拷贝（`capture_multi` / `capture_after` / `capture_ret_multi`），
不要事后 `read_memory`。事后读到的任何东西都要先证明它不是复用内存。

## 4. 读错寄存器

**现象**：`capture_after` 配 `ptr_arg:0`，一直 `unreadable`，读到 `0x0`。

**真相**：`x0` 在函数返回后是**返回值**，不是出参指针。函数返回 0（成功码）时
`bufPtr = 0`，当然读不到。

**规则**：ObjC 方法 `x0=self`、`x1=_cmd`、参数从 `x2` 开始。
C 函数参数从 `x0` 开始。`capture_after` 用的是入口寄存器，`capture_ret_multi` 用的是返回寄存器。

## 5. 排除法的判据本身不成立

**现象**：我说「AES 解密后没有可打印明文 → 不是 AES」。

**真相**：明文是 **protobuf 序列化结果**，本来就不是可打印字符。这条判据从一开始就不成立。

**规则**：排除一个算法前，问自己：**如果它确实是那个算法，这个判据还会成立吗？**
不会成立，就不能用来排除。

## 6. 长度约束被忽略

比「猜算法」更省力的是「用长度砍候选」：

- 输出长度不是 16 的倍数 → 不可能是带 padding 的 AES-CBC/ECB
- 输出长度不是 4 的倍数 → 不可能是 XXTEA
- 输出长度 = 明文长度 → 流密码 / XOR / 自研变换

实测：七鲜 `b4` 的原始字节是 308/309/310/536/537 五个值（39 条样本），`len % 16` 是 4/5/6/8/9，
**排除带 padding 的 AES-CBC/ECB**。但 `536 % 4 == 0`，所以 **XXTEA 没有被排除** ——
我一开始用 3 个样本算出「535/536/537，都不是 4 的倍数」就宣布排除 XXTEA，那是错的。

## 7. 单次观察不是规律

**现象**：同一个输入调两次，输出一样，于是判断「这是纯函数」。

**真相**：可能只是内部状态恰好相同（比如 thread-local 计数器初值相同）。

**规则**：至少 5 次。而且要试「换线程/换进程」——
七鲜的 `b6` 单进程内看起来稳定，但**跨进程是否不同还没验证**（这是待确认项，不要当结论用）。

## 8. 「代码存在」≠「代码执行」

反汇编里看到 `cmp #0x26` 就以为是 `opcode == 38` 的判断——
实际上那是不透明谓词或完整性校验。只有运行时断点能告诉你哪个分支真的走了。

## 9. 统计要穷尽，不要抽样

「我看了 20 个 handler，都没有 mul」不等于「这个 VM 不做乘法混合」。
要扫描全部（得物 dhw 的 VM 分析是 1399 条 `mul` 逐条分类 —— 注意那是另一个目标，别混到七鲜上）。

抽样得出的负面结论，写进报告时必须标明「抽样，N=20」。

## 10. 别相信「看起来合理」

最危险的证据是「数值看起来对」。
一个哈希值看起来像哈希、一个时间戳看起来像时间戳、一段 hex 看起来像密文——
这些都不能证明它来自你以为的那个位置。

**只有「在已知地址、已知时刻、由已知代码路径产生」的字节才算证据。**
